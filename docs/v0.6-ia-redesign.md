# v0.6 页面功能设计重构：「画廊优先」信息架构

> 立项时间：2026-09-10　决策方式：PM 梳理 + 决策人四问确认
> 背景诊断：v0.5 现状 7 个平级视图（示例库/工具箱/5 主题）中，同一功能存在多套入口与实现，
> 核心用户旅程被拆散在多个视图，且存在 3 个实现级断点（见 §6）。
> 本方案方向：**拆散旧工作台，卡片示例与工具成为主角，只保留一处最基础的代码运行**。

## 1. 决策记录（2026-09-10，决策人确认）

| # | 决策项 | 结论 |
|---|---|---|
| D1 | 顶层导航结构 | **三视图**：示例画廊 / 工具箱 / 代码运行器 |
| D2 | Monaco 编辑 + 保存回写 | **详情页内编辑**：点开卡片详情才出现编辑器，可改可存 |
| D3 | 「高质量卡片示例」产出方式 | **质量分驱动**：复用 `app/quality.py` 六维评分，全量示例皆卡片，按分排序 + 分数徽章（`list_examples` 已返回 `quality_score`，零后端改造） |
| D4 | 功能取舍 | **全保留**：参数表单、运行历史+收藏、AI 代码解释、资源上传 |

## 2. 目标信息架构

```text
顶栏: [✨ 示例画廊] [🧰 工具箱] [⌨️ 运行器]        🕘 历史 ⚙️ AI设置 🌙 ↻
底栏: sidecar 状态 · 示例计数 · 运行状态（顶栏状态指示删除，只留底栏一处）

示例画廊（默认视图，全屏）
├── 筛选条: 搜索 · 主题维度 chips · ⭐只看收藏 · 运行状态 · 标签 TopN · 质量分
└── 卡片网格（全量示例，默认按质量分降序）
    └── 点卡片 → 卡片详情页（视图内替换，带返回）

工具箱
├── 搜索 + 收藏/运行状态/标签筛选
└── 工具卡片网格 → 点卡片 → 卡片详情页（同一组件）

代码运行器（最基础）
└── 左: 示例快速搜索 + 只读代码预览
    右: 单行参数输入 + ▶运行/■停止 + 终端输出 + 结果图片

全局弹窗: 运行历史 · AI 设置；浮动面板: AI 解释（挂详情页）
```

**核心变化**：主题从导航 tab 降级为画廊筛选维度；三级树与侧栏整体退场；
主题卡片模板升级为全站统一的卡片范式；详情页成为唯一的「重交互」场所。

## 3. 各视图功能规格

### 3.1 示例画廊（默认首页）

- **筛选条**（一行，可折叠）：搜索框；主题 chips（全部 / Turtle / Pygame / OpenCV / PIL / 数据可视化）；
  ⭐ 只看收藏；运行状态（成功过 / 失败过 / 未运行）；标签 TopN chips；质量分阈值（如 ≥7）。
  全部维度经 `filter-engine` 组合查询（新增 `theme`、`quality` 两个维度，见 §5.3）。
- **卡片网格**：全量示例。默认按质量分降序，可切换按名称 / 最近运行排序。
- **卡片内容**：类型图标 · 标题 · 一行描述（line-clamp）· 标签 ≤2 · 质量分徽章 · 收藏星。
  hover 显现 [▶ 运行] [详情]。
- **卡片 ▶ 运行**：无参数要求 → 直接运行，结果落在详情页输出区（自动打开详情）；
  存在必填参数 → 跳详情页填参后运行。

### 3.2 卡片详情页（画廊 / 工具箱共用组件）

自上而下：

1. **头部**：← 返回 · 标题 · 标签 · 质量分 · [☆ 收藏] [✨ AI 解释] [▶ 运行]
2. **源码**：Monaco 可编辑（D2）· ● 未保存标记 · 💾 保存回写 JSON 真相源（快捷键 Cmd+S 仅在此生效）
3. **参数表单**：argparse 静态解析结果，无参数则整区隐藏（工具类示例默认展开）
4. **运行输出**：状态点 · ■ 停止 · 清空 · 终端输出 · **结果图片网格**（接通 `run_images`，支持下载）
5. **资源**：上传 / 列表 / 删除（自主题详情页迁来，对**所有**示例开放，消除功能孤岛）
6. **此示例的运行历史**：`runHistory` 按 id 过滤，最近 N 条，带重跑按钮
7. **AI 解释**：右侧滑出面板，上下文 = 当前详情页代码的选中片段或全文（修复 `state.currentExample` 幽灵引用）

> 说明：D2+D4 全保留的组合使详情页事实上承载了原「工作台」的完整能力；
> 与旧方案的本质区别是**画廊优先、按需进入**——浏览零负担，深度交互集中在详情一处，
> 不再常驻一个 24 小时挂在大半个屏幕上的编辑器 + 输出区。

### 3.3 工具箱

- 工具卡片网格（`category=tools`）+ 搜索 + 收藏 / 运行状态 / 标签筛选（复用画廊筛选组件）。
- 点卡片进入与画廊**同一个详情组件**；工具通常自带 argparse，参数区置顶默认展开。

### 3.4 代码运行器（最基础，D1 的第三视图）

- **左**：示例快速搜索（输入 → 下拉匹配 → 选中，支持收藏置顶）+ 只读代码预览。
- **右**：单行参数文本框（原始命令行风格，空格分隔，替代参数表单——这是「最基础」的参数方式）·
  ▶ 运行 / ■ 停止 · 终端输出 · 结果图片。
- **明确不做**：编辑（去详情页）、资源、AI 解释、参数表单。
- 可选增强（默认不做，见 §7）：升级为「草稿纸」自由跑代码，需 sidecar 新增 `run_code` RPC。

### 3.5 全局

- **运行历史**：顶栏弹窗保留（重跑 / 清空 / 导出 .log）。重跑行为改为
  「切换到对应视图 → 打开该示例详情 → 填好参数」，替换现有 `setTimeout(120ms)` hack。
- **收藏**：卡片星标 + 详情页按钮；「只看收藏」是筛选条上的一个 chip。
- **明暗主题 / sidecar 状态**：保留；状态指示只留底栏一处。

## 5. 技术改造点

### 5.1 P0 断点修复（不改结构，立即可做）

1. **接通 `run_images`**：sidecar 已发通知（`server.py:448`）、preload/sidecar-client 管道齐全，
   渲染层无订阅者；`renderThemeImages` 为死代码。README 宣传的「结果图片预览」当前不可用。
   已修复（app.ts 订阅 + 输出面板图片条 + 主题抽屉渲染）。
   已知限制：图片为 `file://` URI，打包模式（file:// 页面）直接显示；dev 模式（http 页面）
   Chromium 会拦截 file:// 子资源，图片不可见——如需 dev 可见，后续可加自定义协议。
2. **AI 解释文件名**：`ai.ts:184` 引用不存在的 `state.currentExample`，恒回退 `example.py`。
3. **状态指示去重**：顶栏与底栏 sidecar 状态重复。

### 5.2 结构改造

- 导航改三分支；`switchView` 收敛为 `gallery / toolbox / runner` + 详情页子状态。
- 新建 `detail-page.ts`：画廊与工具箱共用的详情组件（源码/参数/输出/资源/历史/AI 七区）。
- 新建 `card-grid.ts`：自主题卡片模板泛化的通用卡片网格（画廊、工具箱共用）。
- 删除：`renderTree` 全家、双输出系统、5 套主题视图 DOM、`initThemeCodeModal`。
- 底栏保留唯一状态指示。

### 5.3 filter-engine 扩维（纯函数 + 单测）

- `theme` 维度：`THEMES[].filter` 收编进引擎，删除 `applyThemeFilters` 特殊分支（同时消灭主题视图「隐身筛选」问题）。
- `quality` 维度：`quality_score` 阈值筛选（字段已随 `list_examples` 返回）。
- 排序：`sortBy: quality_desc | name | last_run`。

### 5.4 其他

- 运行器单行参数 → `args[]` 的简单拆分（shlex 风格，处理引号）。
- 历史「重跑」新流程；AI 解释上下文绑定详情页。
