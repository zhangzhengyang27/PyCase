## 5. 数据契约重设计（强制条件）

设计稿见 [数据契约 v2 设计稿](redesign-data-contract.md)（B1 产出，含实测数据与护栏映射；已对稿，B2 按此实现）。

对稿记录（2026-09-29）：内容载体 = **外移为真实 .py 源码树**（清单 JSON 只存元数据，既有目录型示例原位保留）；
派生事实 = 构建期烘焙 + 启动哈希校验；资产保全 = 基线与用户资产分离；缓存上限 = 1GiB + LRU + 手动清理。
由此的硬约束：v1 应用不可读 v2 清单（单向破坏，由迁移备份/回滚 + 逐条校验放行兜底）；`scripts/` 生成器类脚本退役。

设计目标（B1 定稿并对稿）：

- **启动不物化**：索引与内容分离（清单/树/索引独立），消除 17s 首载（C2；本机组件分解实测见设计稿 §1）。
- **schema_version 显式化**：每集合带版本；user_examples 与内置同构。
- **缓存版本化**：可重建、可清理、有容量上限（C2）。
- **迁移工具**：dry-run + 备份 + 回滚开关；老格式只读兼容一个版本周期；迁移演练先在副本上跑。
- **逐条校验**：1496 条语义等价断言通过后才允许切换真相源。

禁止项：无迁移工具的破坏性变更；未演练的切换。

## 7. 「大厂级」验收标准

| 维度 | 目标（可检验） | 检验方式 |
|---|---|---|

## 10. 变更管理与治理

- **评审门禁**：方案、计划、以及任何删减或降级既有功能的改动，必须先对稿；里程碑结束交付可验证 Demo。
- **提交规范**：沿用现有 fix()/feat() 前缀；破坏面大的阶段用独立工作树隔离，主干保持可运行。
- **文档治理**：新增/更新文档过 check_doc_refs；过期文档按仓库既有惯例加存档标注；版本号收敛为单一来源（B2 落地）。
